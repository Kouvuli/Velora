# Project knowledge

What is known about THIS project. Managed with `ai-skills knowledge ...`.

- One fact or topic per Markdown file, in the matching folder.
- Frontmatter `status`: CONFIRMED | INFERRED | UNKNOWN | STALE | CONFLICTING.
- CONFIRMED requires `evidence:` (file paths). Never upgrade INFERRED to CONFIRMED without evidence.
- Source of truth order: code > tests > schema > API contracts > requirements > ADRs > docs > this index > inference.
- `index/facts.yaml` is generated by `ai-skills knowledge discover` (stack facts with file evidence).
- `index/graph.yaml` (also generated) links components, endpoints, entities, tables and technologies; every edge
  cites file:line. Query it with `ai-skills knowledge graph <name>`. It is an index: check the cited source.
- `requirements/` holds the features and epics (stories, acceptance criteria, revision, approval) and `work/` the
  tickets. People author them through the requirements / planning skills; they are the source of truth for what to
  build, so they carry no `evidence:`. `knowledge check` validates their IDs, story/criterion mapping and approval.
- Run `ai-skills knowledge check` to find stale or unsupported items.
- `engagement/` (client intake, estimates, status log, retrospective) is PRIVATE to you and git-ignored by default:
  client repositories are often client-owned. Never move rates, contacts or internal notes into shared files.

Template:

```markdown
---
title: <one-line claim>
status: INFERRED
evidence:
  - path: <relative/path>
---
Details, with links to code.
```
